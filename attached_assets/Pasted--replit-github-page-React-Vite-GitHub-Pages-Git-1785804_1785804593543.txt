## 프로젝트 개요

[프로젝트명] replit 내용을 github page로 이관

아키텍처:
- 프론트엔드: React + Vite → GitHub Pages (GitHub Actions 자동 배포)
- 백엔드: Cloudflare Workers (TypeScript) — OpenAI 호환 AI API 프록시 + tool calling
- AI 모델: [모델명, 예: MiniMax-Text-01 / gpt-4o / claude-3-5-sonnet]
- API Base URL: [예: https://api.minimaxi.chat/v1 / https://api.openai.com/v1]

## 2. Cloudflare Worker (cloudflare-worker/src/index.ts)

다음 패턴으로 Worker를 작성해 줘:

### 2-1. Env 인터페이스
```typescript
export interface Env {
  AI_INTEGRATIONS_OPENAI_API_KEY: string;   // AI API 키 (wrangler secret)
  AI_INTEGRATIONS_OPENAI_BASE_URL: string;  // API Base URL (wrangler.toml vars)
  AI_MODEL: string;                         // 모델명 (wrangler.toml vars)
  ALLOWED_ORIGIN: string;                   // 허용 Origin (wrangler.toml vars)
  // 필요한 외부 API 키 추가
  [API_KEY_NAME]: string;
}
```

### 2-2. 동적 시스템 프롬프트 (날짜 주입 필수)
```typescript
function buildSystemPrompt(): string {
  const kst = new Date(Date.now() + 9 * 60 * 60 * 1000);
  const dateStr = kst.toISOString().slice(0, 10);
  return `[역할 및 지침]
오늘 날짜(KST): ${dateStr}
사용 가능한 도구: [도구 목록]

}
```
→ 절대 const SYSTEM_PROMPT = "..."처럼 정적으로 만들지 말 것. 날짜가 고정된다.

### 2-3. Tool Calling Loop (최대 8회 반복)
```typescript
const maxIter = 8;
let iterCount = 0;
let continueLoop = true;
let finalMessage = "";

while (continueLoop && iterCount < maxIter) {
  iterCount++;
  const aiRes = await fetch(`${openaiBase}/chat/completions`, {
    method: "POST",
    headers: { "Content-Type": "application/json", Authorization: `Bearer ${openaiKey}` },
    body: JSON.stringify({
      model: env.AI_MODEL,
      max_completion_tokens: 8192,
      messages: chatMessages,
      tools: TOOLS,
      tool_choice: "auto",
    }),
  });

  const aiData = await aiRes.json();
  const assistantMsg = aiData.choices?.[0]?.message;

  if (assistantMsg.tool_calls?.length > 0) {
    // 도구 실행 후 결과를 chatMessages에 추가
    chatMessages.push({ role: "assistant", tool_calls: assistantMsg.tool_calls, content: assistantMsg.content ?? null });
    for (const tc of assistantMsg.tool_calls) {
      const result = await executeTool(tc.function.name, JSON.parse(tc.function.arguments), env);
      chatMessages.push({ role: "tool", tool_call_id: tc.id, content: result });
    }
  } else {
    finalMessage = assistantMsg.content || "";
    continueLoop = false;
  }
}
```

### 2-4. CORS 처리

const corsHeaders = {

### 2-6. 오류 처리 패턴
외부 API가 특정 오류(예: IP 차단, 인증 오류)를 반환할 때는 원시 오류 메시지 대신
사용자 친화적인 안내 메시지로 변환해서 반환할 것:
```typescript
const msg = data?.result || data?.message || "";
if (msg.includes("인증 실패") || msg.includes("IP")) {
  return JSON.stringify({ notice: "현재 환경에서 이 기능은 제한됩니다. [대안 안내]" });
}
```

## 3. wrangler.toml

```toml
name = "[worker-이름]"
main = "src/index.ts"
compatibility_date = "2025-04-30"
compatibility_flags = ["nodejs_compat"]
account_id = "[Cloudflare 계정 ID]"

[vars]
ALLOWED_ORIGIN = "https://[GitHub계정].github.io"
AI_INTEGRATIONS_OPENAI_BASE_URL = "[API Base URL]"
AI_MODEL = "[모델명]"
```

비밀 키는 절대 wrangler.toml에 넣지 말고, 배포 후 `npx wrangler secret put [키이름]`으로 등록할 것.

## 4. 프론트엔드 (React + Vite)

### 4-1. 채팅 UI 필수 기능
- 메시지 입력 + 전송 (Enter 키 지원)
- 스트리밍 없이 Worker `/api/chat` 에 POST → 응답 후 렌더링
- 로딩 스피너 표시
- toolCalls 배열을 접을 수 있는 "도구 호출 내역" 섹션으로 표시 (디버깅용)
- Markdown 렌더링 (react-markdown 또는 marked)

### 4-2. Worker URL 환경변수
```typescript
// vite.config.ts
define: { __WORKER_URL__: JSON.stringify(process.env.VITE_WORKER_URL || "https://[worker-이름].workers.dev") }
```
`.env.local`에 `VITE_WORKER_URL=http://localhost:8787` (개발용)

### 4-3. GitHub Pages base path
```typescript
// vite.config.ts
base: process.env.NODE_ENV === "production" ? "/[레포지토리명]/" : "/"
```

## 5. GitHub Actions (GitHub Pages 자동 배포)

`artifacts/[앱이름]/.github/workflows/pages.yml` 파일을 만들어줘:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
    paths: ["artifacts/[앱이름]/**"]

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: "npm"
          cache-dependency-path: "artifacts/[앱이름]/package-lock.json"
      - run: npm ci
        working-directory: artifacts/[앱이름]
      - run: npm run build
        working-directory: artifacts/[앱이름]
        env:
          VITE_WORKER_URL: https://[worker-이름].workers.dev
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: "artifacts/[앱이름]/dist"
      - id: deployment
        uses: actions/deploy-pages@v4
```

GitHub 레포 Settings → Pages → Source를 "GitHub Actions"로 설정할 것.

## 6. Worker 배포 방법

```bash
# cloudflare-worker 디렉토리에서
npm install
npx wrangler deploy

# API 키 등록 (배포 후)
npx wrangler secret put AI_INTEGRATIONS_OPENAI_API_KEY
npx wrangler secret put [기타 API 키]
```

Replit에서는 `CLOUDFLARE_API_TOKEN` 시크릿을 환경변수로 설정하면
`CLOUDFLARE_API_TOKEN="$CLOUDFLARE_API_TOKEN" npx wrangler deploy`로 배포 가능.

## 7. 도구(Tool) 정의 패턴

각 도구는 다음 형식으로 정의:
```typescript
{
  type: "function",
  function: {
    name: "tool_name",
    description: "도구 설명 — AI가 언제 이 도구를 써야 하는지 명확하게",
    parameters: {
      type: "object",
      properties: {
        param1: { type: "string", description: "파라미터 설명" },
        param2: { type: "number", description: "파라미터 설명" },
      },
      required: ["필수파라미터"],
    },
  },
}
```

`executeTool(name, args, env)` 함수에서 `if (name === "tool_name") { ... }` 패턴으로 분기.

## 8. 핵심 주의사항

1. **시스템 프롬프트는 반드시 함수로** — `buildSystemPrompt()` 형태로 현재 날짜를 런타임에 주입
2. **청원·일정류 API에 AGE 파라미터** — 22대 국회 데이터가 필요하면 `AGE: 22` 추가
3. **날짜 파라미터 기본값** — AI가 날짜를 누락할 수 있으므로 도구 구현부에서 현재 날짜를 기본값으로 설정
4. **Worker 시크릿 분리** — API 키는 절대 코드나 toml에 넣지 말고 `wrangler secret`으로 관리
5. **CORS origin 검사** — `github.io`와 `localhost`는 허용, 그 외는 `ALLOWED_ORIGIN`으로 제한
6. **외부 API IP 차단** — 일부 공공 API(법제처 등)는 Cloudflare Worker IP를 차단함. 오류 감지 후 친절한 안내로 변환

## 9. 도구별 주의사항 (이 프로젝트에서 검증된 사항)

[이 섹션은 적용하는 API에 맞게 교체]

현재 프로젝트(국회 API) 기준:
- `ALLSCHEDULE` API: `SCH_DT` 파라미터 형식은 `YYYY-MM`
- `PTTJUDGE` (청원) API: `AGE=22` 필수
- `law.go.kr` (법제처): Cloudflare Worker IP 차단 → 오류 메시지 변환 처리 필요
- MiniMax 모델은 청원·일정 도구를 간혹 스킵 → 시스템 프롬프트에 "반드시 이 도구를 사용하세요" 명시
```

**사용 방법:**
1. 위 프롬프트의 `[대괄호]` 부분을 새 프로젝트에 맞게 채운다
2. 새 Replit 프로젝트를 열고 Agent에게 붙여넣기
3. Cloudflare 계정 ID와 API 키를 준비해 Replit Secrets에 등록
4. Agent가 코드를 생성하면 wrangler deploy → GitHub Actions 순서로 배포
